# NIRS — клиент для ОС Аврора

Нативное приложение Qt/C++ + QML/Sailfish Silica. Целевая платформа — ОС Аврора 5.x,
Qt 5.6+, Aurora SDK с `auroraapp`. Все рабочие данные поступают из HTTP API.
Встроенных демонстрационных данных и подмены серверных ответов нет.

## Возможности

- Вход, регистрация с подтверждением пароля и выход.
- Рабочее пространство с последними четырьмя чатами и запусками.
- Поиск и создание чатов, история и отправка сообщений ассистенту.
- Список и описание пайплайнов, запуск и история запусков выбранного пайплайна.
- Фильтры запусков по ID пайплайна и результату.
- Детали запуска, задачи и опрос статуса через 5 секунд после предыдущего ответа.
- Детали задачи, переход к запуску, загрузка и копирование текстового журнала.
- Настраиваемый адрес сервера, состояния загрузки, пустых списков и ошибок.

## Совместимость с проектом

Контракт взят из `NIRS_VKR/templates/README.md` и `static/js/api.js`.
Серверные JSON-методы теперь реализованы. Для входа создайте аккаунт на сервере
(пароль от 8 символов); чаты требуют доступной Ollama, прогоны — настроенного GitHub.
Новые состояния сервера добавлены в `Contract.js`. Сборка и запуск самого клиента
по-прежнему требуют проверки в установленном Aurora SDK.

Адреса и проверка ответов находятся в `qml/js/Contract.js`. Ожидаемые маршруты:

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/auth/send` | Вход: `{email,password}` → `{access_token,token_type}` |
| POST | `/auth/register/send` | Регистрация: `{email,password}` → JSON или 204 |
| GET | `/api/chats?q=...` | Чаты |
| POST | `/chats/new` | Новый чат: `{}` → `{id}` |
| GET | `/api/chats/{id}` | Чат с `messages` |
| POST | `/api/chats/{id}/messages` | `{content}` → `{assistant_message:{role,content}}` |
| GET | `/api/pipelines` | Пайплайны |
| GET | `/api/pipelines/{id}` | Описание пайплайна |
| POST | `/pipelines/{id}/start` | Новый запуск: `{}` → `{id}` |
| GET | `/api/runs?pipeline_id=...&result=...` | Запуски |
| GET | `/api/runs/{id}` | Запуск с `jobs` |
| GET | `/api/runs/{id}/status` | Полный актуальный запуск с `jobs` |
| GET | `/api/jobs/{id}` | Задача |
| GET | `/jobs/{id}/log` | Журнал `text/plain; charset=utf-8` |

Списки — массив либо `{items:[...]}`; ID — непустая строка или число, включая 0.
Идентификаторы и параметры поиска кодируются. Подробные поля объектов и формат дат
определены в исходном `templates/README.md`. Сервер должен проверять Bearer-токен
и доступ пользователя ко всем приватным объектам. Ключи GitHub Actions клиенту не нужны.

## Сборка и запуск

1. Откройте `ru.nirs.Client.pro` в Aurora IDE.
2. Выберите установленный комплект Аврора 5.x под архитектуру устройства/эмулятора.
3. Выполните сборку и развёртывание через IDE. Описание RPM: `rpm/ru.nirs.Client.spec`.
4. При первом запуске откройте верхнее меню → «Настройки сервера».
5. Укажите корень сервера, например `https://nirs.example.org`, без суффикса `/api`.
   Если API размещён под префиксом, используйте `https://host/nirs`.
6. Войдите, когда сервер начнёт поддерживать перечисленные JSON-методы.

На физическом устройстве `127.0.0.1` означает само устройство. Для сервера на
компьютере используйте доступный устройству IP или DNS-имя. Начальный адрес
`http://127.0.0.1:8000` предназначен для разработки. Для рабочего подключения
используйте HTTPS с доверенным сертификатом; обход ошибок TLS не предусмотрен.

В пакете только сетевое разрешение `Internet`. Идентификатор приложения:
`ru.nirs.Client`. Перед распространением укажите собственную организацию,
лицензию и настройте подпись пакета в SDK. Метаданные лицензии сейчас Proprietary;
добавлять открытую лицензию без решения владельца исходников нельзя.

## Сессия и сетевые сбои

Токен хранится только в памяти процесса; пароль не сохраняется. Адрес сервера
сохраняется через QSettings. После перезапуска требуется вход. Выход и смена
сервера отменяют активные запросы и отбрасывают запоздалые ответы. Ответ 401
на приватный запрос очищает сессию и открывает вход; это локальный выход,
нативный выход очищает токен локально. Сервер поддерживает `/auth/logout`,
но нативный клиент пока его не вызывает; токен истекает через 24 часа.

Перенаправления HTTP запрещены. Cookies не загружаются и не сохраняются.
Таймаут — 120 секунд, предел ответа — 8 МиБ. JSON/журнал проверяются по типу
содержимого. Сообщения, имена и журналы отображаются как обычный текст.

POST не повторяется автоматически. После неуспешной отправки сообщения поле
сохраняет текст, а повторная отправка блокируется до обновления истории.
После ошибки запуска нужно обновить список запусков перед повтором. При потере
ответа сервер мог уже выполнить действие; клиент без серверной идемпотентности
не может гарантировать отсутствие дублей. После ошибки создания чата повторное
создание также блокируется до обновления списка.

Опрос запуска прекращается после завершения, ошибки, ухода со страницы и
сворачивания приложения. При возврате активный запуск обновляется заново;
после ошибки опрос возобновляется вручную через верхнее меню.

## Проверки

Проверка общего с интерфейсом контракта без SDK (Node.js):

```sh
node tests/contract.test.cjs
```

Проверки HTTP-транспорта с локальной TCP-фикстурой, без бэкенда и аккаунта GitHub
(в окружении с Qt 5 development tools и Qt Test):

```sh
mkdir -p build-tests
cd build-tests
qmake ../tests/transport.pro
make
./transport-tests
```

Тесты транспорта проверяют JSON/Bearer, вход без токена, 401, запрет редиректов,
HTML вместо JSON, повреждённый JSON, 204, текстовые журналы, ошибки валидации,
отмену запросов и смену сервера. Они не требуют `auroraapp` или Silica.

В исходной среде разработки нет Qt/Aurora SDK: выполнены только Node-проверки
контракта и статическая проверка файлов. C++-тесты, RPM, внешний вид и поведение
на устройстве требуют отдельного запуска в SDK. Полную интеграцию нужно
подтвердить запуском клиента с реализованным сервером и доступным GitHub.

Перед приёмкой на устройстве проверьте вход и выход, поворот экрана/клавиатуру,
длинные сообщения и логи, поиск с кириллицей, пустые списки, сетевой обрыв при
отправке, возврат из задачи в выполняющийся запуск, сворачивание приложения,
ошибки 401/403/404/422/429/500 и успешную установку подписанного RPM.
