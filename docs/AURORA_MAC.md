# Сборка клиента Авроры на Mac Apple Silicon

Проверено 13 ноября 2026 на Mac ARM64 с 16 ГБ памяти, Docker Desktop
(8 ГБ для Docker), Aurora BT 5.2.1 и apptool 0.3.16. Отдельный Linux-сервер
для компиляции не требуется: среда ARM64 запускается в Docker на Mac.

## Повторить сборку

Запустите Docker Desktop, затем из корня проекта:

```sh
bash scripts/build-aurora-bt.sh
```

Сценарий скачивает официальный образ, закреплённый по SHA256, копирует только
исходники клиента во временную папку и выполняет `apptool build --arm64`.
Сборка, подпись и валидация обязательны; их ошибки завершают сценарий.
Результат: `artifacts/rpm/ru.nirs.Client-0.1.0-1.aarch64.rpm`,
журнал: `artifacts/rpm/build.log`. Временная копия удаляется автоматически.
`ARTIFACT_DIR` позволяет выбрать каталог результата, `AURORA_ARCH` — целевую
архитектуру (`arm64`, `arm32`, `x64`). Проверена только ARM64 на ARM64-хосте.

Используется стандартный тестовый сертификат SDK. Это не подпись для публикации
в магазине. Полная IDE и эмулятор для самой сборки не нужны.

## Подтверждено

- Компиляция C++/Qt и создание RPM для Авроры ARM64.
- Подпись и проверка пакета через apptool без отключения валидации.
- Чистая сборка через приведённый сценарий.
- C++-тесты HTTP-транспорта в ARM64-контейнере: 13 passed, 0 failed.
- JS-контракт: все 8 групп прошли.

Журналы первоначальной проверки находятся в `artifacts/aurora-bt-check/`.
Установщик Mac ARM64 скачан в `sdk/` и проверен по официальному MD5:
`f6631fb254a8706e1dfcf5df020d2641`. Для приведённой команды он не требуется.
SDK и результаты сборки исключены из Git.

## Эмулятор на Mac

14 ноября 2026 установлен полный Aurora BT 5.2.1 в `sdk/AuroraBT-5.2.1`.
Лицензия подтверждена пользователем. Эмулятор ARM64 загрузился (2 CPU, 4 ГБ RAM),
RPM установлен через SDK. Системный запрос доступа к интернету и уведомлениям
подтверждён пользователем. Клиент запущен в штатной песочнице, экран входа
проверен визуально. C++-тесты транспорта выполнены также непосредственно
в гостевой ОС Аврора: 13 passed, 0 failed.

После настройки сервера и входа пользователем подтверждены регистрация (201),
авторизация (200), получение чатов, прогонов и пайплайнов (200). В эмуляторе
визуально проверен список реальных пайплайнов «Проверка портала» и
«Сборка клиента Авроры». Снимок: `artifacts/validation/aurora-client-connected.png`.

Команды из корня проекта:

```sh
SFDK="./sdk/AuroraBT-5.2.1/Qt Creator.app/Contents/MacOS/sfdk"
"$SFDK" emulator start
"$SFDK" -c 'device=Aurora OS эмулятор 5.2.1.200' deploy --sdk --silent \
  artifacts/rpm/ru.nirs.Client-0.1.0-1.aarch64.rpm
"$SFDK" emulator exec -- invoker --type=silica-qt5 --single-instance \
  /usr/bin/ru.nirs.Client
```

Адрес сервера Mac из эмулятора: `http://10.0.2.2:8000`.
Доступность `/health/ready` по этому адресу подтверждена из гостевой Авроры.
`127.0.0.1` внутри эмулятора обозначает само виртуальное устройство.
Адрес меняется кнопкой «Настроить сервер» на экране входа. Также доступен
пункт «Настройки сервера» в верхнем вытягиваемом меню.
Дополнительные аргументы запуска отсутствуют в desktop-манифесте и не должны
передаваться через invoker: песочница Авроры отклоняет такие команды.

Для остановки: `"$SFDK" emulator stop`.
В этой поставке BT команда sfdk выводит предупреждение конфигурации Build Engine;
оно не помешало загрузке эмулятора, выполнению команд и установке RPM.
Журналы установки и запуска: `artifacts/aurora-bt-check/emulator-*.log`.
Локальные ключи подписи, создаваемые SDK в `.auroraos-*-keys/`, исключены из Git.

## Автоматическая проверка реального API и модели

`aurora_client/tests/live_api_test.cpp` использует настоящий `ApiClient` с
локальным сервером и Ollama, а не подменой ответов. Внутри Авроры проверены
вход, список пайплайнов, чат с реальным ответом, история и отзыв сессии.
Тест не нажимает кнопки интерфейса и не подтверждает поведение QML.

Для повторения нужны запущенные Docker Compose, Ollama с `qwen3.5:9b`, эмулятор
и известный SSH-ключ эмулятора в локальном `sdk/emulator-known-hosts`.
Скопируйте свежие исходники и скомпилируйте тест официальным ARM64-образом:

```sh
mkdir -p artifacts/aurora-bt-check/source
cp -R aurora_client/. artifacts/aurora-bt-check/source/
docker run --rm --platform linux/arm64 --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$PWD/artifacts/aurora-bt-check/source,dst=/sources" \
  --workdir /sources \
  hub.omp.ru/public/sdk-build-tools@sha256:ee8a3a16192c10ef3de252f9be13f93102db73a0c1ddbefe214a9b3c62553115 \
  bash -lc 'mkdir -p live-build; cd live-build; qmake ../tests/live_api.pro && make -j2'
.venv/bin/python scripts/check-aurora-live.py
```

Сценарий запускает бинарный тест в гостевой Авроре, создаёт уникальный временный
аккаунт и удаляет только его записи в блоке `finally`, включая случай ошибки.
Секрет сессии и пароль не выводятся. Для очистки используется локальная БД этого
Docker Compose; запускать сценарий следует только для данного локального проекта.
Выход 0 означает успех теста и успешную очистку.

Журнал: `artifacts/aurora-bt-check/emulator-live-api.log`,
итог: `artifacts/validation/aurora-live-api-summary.json`.
