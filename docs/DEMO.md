# Демонстрация MVP НИРС

## Подготовка на этом Mac

1. Запустить Docker Desktop и Ollama.
2. Из корня проекта выполнить `docker compose up -d --build --wait`.
   На новой машине сначала нужны `.env`, модель и сборка образа по README.
3. Проверить `http://localhost:8000/health/ready`: ожидается `status: ok`.
4. Открыть `http://localhost:8000`, войти в свой аккаунт.
5. На главной странице проверить доступность Qwen3.5 9B и настройку GitHub.

Ключ GitHub хранится в локальном `.env`. После замены ключа пересоздать app:
`docker compose up -d --no-build --force-recreate --wait app`.
Не показывать `.env`, содержимое ключей и настройки токенов на демонстрации.

## Карточка сбоя у стенда

1. На главной странице веб-портала или клиента «Аврора» нажать «Описать сбой».
2. Заполнить карточку вымышленными данными из таблицы.
3. Вставить журнал в клиенте «Авроры» или сохранить строки в `stand.log`
   и приложить файл через веб.
4. Сохранить сессию. Записать ручную проверку и запросить черновик.
   Сверить факты, гипотезы и поля отчёта с карточкой.
5. На телефоне скопировать ответ. В вебе скачать его как текст.
   Повторно войти и открыть сессию и историю анализа.
6. После подтверждения результата отметить сбой решённым. При повторном
   воспроизведении его можно переоткрыть.

| Поле | Демонстрационные данные |
| --- | --- |
| Краткое название | Тайм-аут исходящего вызова |
| Стенд | CALL-01 |
| Устройство и сборка | DEMO-01, сборка 1.2.3 |
| Шаги | Запустить тест исходящего вызова и дождаться результата. |
| Ожидаемый результат | Состояние CONNECTED появляется за 15 секунд. |
| Фактический результат | По истечении 15 секунд тест завершился с тайм-аутом. |

```text
INFO test=outgoing_call state=DIALING
ERROR test=outgoing_call expected=CONNECTED timeout_ms=15000
INFO result=failed
```

Эмулятор можно настроить по [инструкции для Mac](AURORA_MAC.md).
Если сервер запущен на Mac и эмулятор использует сеть NAT, укажите
`http://10.0.2.2:8000` в настройках клиента.

## Импорт результата стенда

В `.env` укажите `TESTOPS_STAND_REPORT=/stand/latest.json` и обновите контейнер
приложения. Для демонстрации выполните:

```sh
python3 scripts/demo-stand.py --connection-ms 16000
```

В сессии `CALL-01` нажмите «Импортировать снимок стенда». Появится проверка
со статусом «Сбой». Повторный импорт той же записи сохранит один результат.
Сформируйте новый снимок с `--connection-ms 9000` и импортируйте его. В истории
будут обе проверки. Подключение реального оборудования требует производителя
снимков в [этом формате](../examples/stand/README.md).

## Разбор автотестов через CI/CD

1. В «Пайплайнах» запустить «Проверку портала» для ветки с изменениями или
   открыть готовый прогон в истории.
2. Сверить статус задачи и число прошедших тестов с журналом GitHub Actions.
3. Из завершённого прогона открыть «Разобрать прогон» и сопоставить ответ
   со статусом и журналом.
4. Создать сессию из исходного завершённого прогона и нажать «Повторить
   связанный прогон». Откроется новый запуск того же workflow на той же ветке.
   После завершения вернуться в сессию и записать результат по ID нового запуска.
5. При необходимости отдельно показать сборку RPM для «Авроры» и скачивание
   артефакта через веб-портал.

## Подтверждения и границы

- [Проверенные сценарии](VALIDATION.md).
- [Архитектура и границы адаптации](ARCHITECTURE.md).
- Локальные журналы и результаты — `artifacts/validation/` и
  `artifacts/aurora-bt-check/`; в Git они не включаются.
- Другие мобильные ОС подключаются отдельным workflow и средствами сборки.
  Проверена Аврора, поддержка остальных ОС не заявляется как реализованная.
- Постоянный сервер и публичное размещение не входят в локальную демонстрацию.
  Для сборки RPM не требуются VPS и отдельная подписка Azure.

После показа: `docker compose stop`. Не использовать `down -v`: это удалит БД.
