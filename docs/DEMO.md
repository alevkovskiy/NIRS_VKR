# Демонстрация дипломного проекта

## Подготовка на этом Mac

1. Запустить Docker Desktop и Ollama.
2. Из корня проекта выполнить `docker compose up -d --no-build --wait`.
   На новой машине сначала нужны `.env`, модель и сборка образа по README.
3. Проверить `http://localhost:8000/health/ready`: ожидается `status: ok`.
4. Открыть `http://localhost:8000`, войти в свой аккаунт.
5. На главной странице проверить доступность Qwen3.5 9B и настройку GitHub.

Ключ GitHub хранится только в локальном `.env`. Текущий ключ действует до
13 декабря 2026; после замены ключа пересоздать app:
`docker compose up -d --no-build --force-recreate --wait app`.
Не показывать `.env`, содержимое ключей и настройки токенов на демонстрации.

## Основной сценарий без эмулятора

1. В разделе пайплайнов выбрать «Сборка клиента Авроры», ветку `main`, запустить
   один раз. Сохранить номер прогона. Сборка выполняется в GitHub Actions
   официальным Aurora BT на стандартном ARM64 runner.
2. Дождаться завершения, открыть задачу, посмотреть журнал. Успех должен
   соответствовать реальному результату GitHub, а не только наличию записи в БД.
3. Скачать `aurora-rpm`: внутри ZIP должен быть ARM64 RPM приложения.
   Пакет подписан тестовым сертификатом SDK, не сертификатом магазина.
4. Нажать анализ завершённого прогона, прочитать ответ и сопоставить его с
   итогом задачи и журналом. Ответ модели требует проверки человеком.
5. Создать обычный чат с ассистентом, отправить короткий вопрос, обновить страницу
   и показать, что история сохранилась.

Проверка самого портала доступна отдельным пайплайном «Проверка портала»:
он выполняет миграции PostgreSQL, серверные тесты и собирает Docker-образ.

## Дополнительная часть с Авророй

Эмулятор и клиент уже установлены, см. [AURORA_MAC.md](AURORA_MAC.md).
Клиент подключается к `http://10.0.2.2:8000`, адрес меняется кнопкой
«Настроить сервер» на экране входа. Вход и получение списков проверены;
полный сценарий интерфейса отложен и не должен выдаваться за пройденный.

## Подтверждения и границы

- [Проверенные сценарии](VALIDATION.md).
- [Архитектура и границы адаптации](ARCHITECTURE.md).
- Локальные журналы и результаты — `artifacts/validation/` и
  `artifacts/aurora-bt-check/`; в Git они не включаются.
- Другие мобильные ОС подключаются отдельным workflow и средствами сборки.
  Проверена Аврора, поддержка остальных ОС не заявляется как реализованная.
- Постоянный сервер и публичное размещение не входят в локальную демонстрацию.
  Для сборки RPM не требуются VPS и отдельная подписка Azure.

После показа: `docker compose stop`. Не использовать `down -v`: это удалит БД.
