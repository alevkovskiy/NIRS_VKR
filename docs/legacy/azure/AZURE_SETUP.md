# Подключение Azure DevOps и сборки Авроры

В репозитории подготовлены код интеграции и два YAML-файла. Организация Azure
ещё не создана; нижеприведённые действия требуют учётной записи владельца проекта.
Токен доступа не нужно отправлять в переписку.

## 1. Создать проект и подключить репозиторий

Откройте https://aex.dev.azure.com/, войдите в Microsoft и создайте организацию
и проект. По документации Microsoft, проверенной 13.11.2026, для создания новой
организации требуется активная Azure-подписка. Создание платной подписки и ввод
платёжных данных выполняет владелец аккаунта; сам по себе бесплатный уровень
Azure DevOps не гарантирует возможность регистрации без подписки.

Источник: https://learn.microsoft.com/en-us/azure/devops/organizations/accounts/create-organization?view=azure-devops
 Подключите GitHub
репозиторий NIRS_VKR либо разместите его в Azure Repos. Изменения этого сеанса
сохранены локально: они не закоммичены и не отправлены автоматически.

Создайте pipeline из существующего файла `azure-pipelines.yml`. Он проверяет
Python-сервер и контракт клиента, выполняет миграции на временной PostgreSQL,
собирает Docker-образ и публикует `portal-image`. Это CI портала, не сборка RPM.

## 2. Подготовить агент с Aurora SDK

Понадобится отдельный Linux x86_64-компьютер/виртуальная машина с официальным
Aurora SDK, рабочим Build Engine и доступным установленным target. Совместимость
конкретной версии SDK с хостом проверяется по документации разработчика.
В стандартных папках текущего Mac комплект не обнаружен.

Установите SDK по инструкциям портала разработчиков и проверьте:

```sh
/path/to/AuroraOS/bin/sfdk tools list
```

В Azure создайте пул `AuroraSDK`, установите self-hosted agent и запустите его
под пользователем, которому доступен SDK и его рабочая директория. Установите
Node.js для проверки JS-контракта. Не используйте этот агент для непроверенных
публичных pull requests.

Создайте отдельный pipeline из `azure-pipelines-aurora.yml`. Задайте в его
переменных:

- `AURORA_TARGET` — точное имя установленного target из `sfdk tools list`.
- `AURORA_WORKSPACE` — рабочая директория, выбранная при установке SDK.
- `SFDK_BIN` — полный путь к исполняемому `sfdk`.

Pipeline копирует исходники во временную папку внутри SDK workspace, выполняет
`sfdk build` и `sfdk check`, публикует `aurora-rpm`. Сначала запустите его вручную
в Azure и убедитесь, что он действительно сформировал RPM. Метаданные и подпись
пакета нужно проверить в установленном SDK перед распространением.

Официальная инструкция sfdk:
https://developer.auroraos.ru/doc/sdk/app_development/build/build_engine/sfdk
Агенты Azure:
https://learn.microsoft.com/en-us/azure/devops/pipelines/agents/agents

## 3. Подключить портал

Создайте отдельный PAT с доступом к нужной организации и минимальными правами
Build: Read & execute. Храните его только в `.env` или серверном хранилище секретов.

```dotenv
AZURE_ORGANIZATION=organization-name
AZURE_PROJECT=project-name
AZURE_PAT=your-private-token
```

Указывайте имена организации и проекта, не полный URL. Заполните локальный `.env`
и пересоздайте приложение:

```sh
docker compose up -d --wait app
docker compose exec app python manage.py add-pipeline --azure-id 42 --name "Сборка клиента Авроры"
```

Замените `42` на ID отдельного pipeline Авроры, а не CI портала. ID видно в URL
Azure `.../_build?definitionId=42`. После этого на сайте появится пайплайн.

Сервис использует Azure DevOps Services (`dev.azure.com`), REST API 7.1.
Azure DevOps Server с произвольным адресом пока не поддержан.
Описание запуска:
https://learn.microsoft.com/en-us/rest/api/azure/devops/pipelines/runs/run-pipeline?view=azure-devops-rest-7.1

## 4. Проверить полный сценарий

1. Войти на сайт, открыть пайплайн, выбрать существующую ветку.
2. Запустить сборку и проверить появление того же запуска в Azure.
3. Дождаться результата и открыть журнал задачи.
4. Скачать ZIP `aurora-rpm`, проверить наличие RPM внутри.
5. Нажать «Разобрать с ИИ», проверить связь чата с прогоном.
6. Сравнить ответ модели с журналом; не принимать гипотезу за выполненную проверку.
7. Повторить с намеренной ошибкой сборки в отдельной ветке.

Если Azure недоступен, сайт не подменяет ответ успешным запуском. Сетевые сбои
с неопределённым результатом требуют ручной сверки, см. ARCHITECTURE.md.

## 5. Постоянный сервер

Для защиты достаточно локального Compose и доступной Ollama. Для удалённого
размещения нужны целевой сервер, DNS/HTTPS, защищённые настройки, резервные копии
PostgreSQL и доступ сервера к модели. Автоматическая доставка не активирована:
адреса и реквизиты целевого сервера не заданы. Подготовлен Docker-образ, который
можно доставить после определения окружения. Миграции запускаются до старта API.

Для этого этапа также подготовлены `compose.production.yaml`, `scripts/deploy.sh`
и ручной `azure-pipelines-deploy.yml`. Это не проверенное внешнее развёртывание:
сервер пока отсутствует. Шаблон ориентирован на Linux x86_64 с Docker, совпадающий
с архитектурой образа CI. Порт приложения на сервере остаётся локальным; HTTPS
предоставляет отдельно настроенный reverse proxy.

Перед активацией CD:

1. На сервере создайте `/opt/nirs-portal/.env` со своими PostgreSQL-реквизитами,
   доступным из контейнера `OLLAMA_URL` и настройками Azure. Не копируйте пароль
   ноутбука. Ollama на Mac не будет доступна удалённому серверу по localhost.
2. Подготовьте SSH-подключение в Azure с доступом к `/opt/nirs-portal` и Docker.
3. Создайте ручной pipeline из `azure-pipelines-deploy.yml`; задайте
   `PORTAL_CI_PIPELINE_ID`, `PORTAL_CI_RUN_ID`, `DEPLOY_SSH_CONNECTION`.
4. Выберите успешную сборку CI. CD скачает её архив образа, перенесёт на сервер,
   создаст резервную копию PostgreSQL, применит миграции и дождётся healthcheck.

Скрипт использует отдельный Compose-проект `nirs-portal-prod`. Откат схемы
автоматически не выполняется. Если миграция прошла, а приложение не запустилось,
нужно проверить совместимость старого образа со схемой; восстановление базы из
резервной копии — отдельная административная операция с возможной потерей новых
данных. Настройка HTTPS, доступа и ротация резервных копий остаются задачами
конкретного окружения. Для сдачи с одного Mac этот CD не требуется запускать.
