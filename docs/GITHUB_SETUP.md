# GitHub Actions без платной подписки

Используется репозиторий `alevkovskiy/NIRS_VKR` и бесплатные стандартные Linux runners
для публичного проекта. Свой runner также бесплатен по текущим условиям GitHub;
хранение артефактов имеет отдельные лимиты. Платные larger runners не используются.
Отчёты и RPM хранятся три дня. SDK и Docker-образы CI в артефакты не загружаются.

Условия: https://docs.github.com/en/billing/concepts/product-billing/github-actions

## Процессы

- `.github/workflows/portal.yml`: проверки PostgreSQL, миграций, API и клиента,
  сборка образа портала, небольшой XML-отчёт. Автоматически запускается при push
  в main/codex/** и pull request, также поддерживает ручной запуск с сайта.
- `.github/workflows/aurora.yml`: ручная сборка RPM на своём Linux x86_64-исполнителе.
- `.github/workflows/deploy.yml`: необязательная ручная доставка на существующий
  сервер с меткой `nirs-deploy`; без такого сервера запускать его не нужно.

Для `workflow_dispatch` файл должен существовать в основной ветке репозитория.
После публикации проверьте вкладку Actions и первый запуск Portal CI.

## Доступ сайта к GitHub

Подключение GitHub к помощнику позволяет публиковать код и проверять CI, но не
передаёт учётные данные запущенному сайту. Для сайта нужен отдельный fine-grained
personal access token: только репозиторий NIRS_VKR, права Actions: Read and write,
короткий срок действия. Другие права для запуска и чтения результатов не требуются.
Не добавляйте токен в Git или переписку. Запишите его только в локальный `.env`:

```dotenv
GH_OWNER=alevkovskiy
GH_REPO=NIRS_VKR
GH_ACTIONS_TOKEN=your-private-token
```

Затем:

```sh
docker compose up -d --wait app
docker compose exec app python manage.py add-pipeline --workflow portal.yml --name "Проверка портала"
docker compose exec app python manage.py add-pipeline --workflow aurora.yml --name "Сборка клиента Авроры"
```

`--verify` дополнительно проверяет наличие workflow через API. Каталог пайплайнов
изменяется локальной административной командой. На сайте выбираются только
разрешённые процессы; загрузка произвольного workflow через браузер не предусмотрена.

## Исполнитель Авроры

Установщик 5.1.2.10 (Linux x86_64) скачан в `sdk/`, проверен по официальному MD5.
Эта папка исключена из Git и Docker-образа. На Mac M4 этот Linux ELF не запускается
непосредственно. Требуется совместимая Linux x86_64-среда с установленным SDK,
Build Engine и target, например на отдельном компьютере/виртуальной машине.

В репозитории откройте Settings → Actions → Runners → New self-hosted runner.
Установите runner на доверенной машине, добавьте метку `aurora-sdk`.
Для установки runner использует короткоживущий регистрационный токен GitHub.
Не публикуйте его и не запускайте на этом исполнителе непроверенные pull requests.
Workflow Авроры разрешает только ручные запуски.

Repository variables:

- `AURORA_TARGET`: установленный target из `sfdk tools list`.
- `AURORA_WORKSPACE`: рабочая директория, выбранная в SDK.
- `SFDK_BIN`: полный путь к sfdk.

Исполнитель должен иметь Node.js для JS-проверок и доступ к SDK под своим
пользователем. После подключения запустите workflow вручную из Actions, затем
из портала. Пока runner не подключён, настоящий запуск GitHub будет ждать в очереди;
это не успешная сборка. Проверка портала может работать независимо от SDK.

## Показ на защите

1. Запустить Docker и Ollama на Mac; войти на сайт.
2. Запустить «Проверка портала», дождаться результата и открыть журнал/отчёт.
3. На подключённом SDK-исполнителе запустить сборку клиента и скачать ZIP с RPM.
4. Разобрать журнал с ИИ, сравнив ответ с фактическим выводом сборки.

## Секреты и повторы

Токен хранится только на сервере. Подписанные ссылки на журналы/артефакты
обрабатываются сервером без передачи GitHub-токена в blob-хранилище.
Веб-клиент передаёт `Idempotency-Key`; внешний dispatch выполняется однократно.
Для восстановления потерянного ответа используется уникальный `portal_request_id`,
путь workflow и ветка — сервер не выбирает просто последний чужой запуск.

Предыдущие файлы Azure сохранены в `docs/legacy/azure/` как неактивный справочный
материал. Они не используются текущим приложением и не требуют Azure-подписки.
