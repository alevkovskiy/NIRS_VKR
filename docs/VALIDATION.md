# Проверка реализации

Проверки выполнены локально 13 ноября 2026 года.

## Реальная инфраструктура

- PostgreSQL 17 в Docker, отдельные базы `nirs` и `nirs_test`.
- Три миграции: первоначальная схема и сессии/аренды/идемпотентные запросы и перенос идентификаторов GitHub.
- Применение, проверка расхождений, полный откат и повторное применение в тестовой базе, включая переименование колонок без удаления таблиц.
- Docker-образ приложения собран; сайт и база проходят healthcheck.
- Настоящая Ollama на Mac, модель Qwen3.5 9B.
- Проверка через API: регистрация временного пользователя → вход → создание чата →
  реальный ответ модели → чтение сохранённой пары сообщений → выход → 401 со старым
  токеном. Простой ответ получен примерно за 8,2 секунды; это одиночный замер,
  не оценка производительности. Повторная проверка с вопросом о qmake также
  прошла: ответ получен примерно за 18,1 секунды. Временный аккаунт после проверки удалён.
- Главная страница и форма входа просмотрены в браузере.

## Автоматические проверки

Все 19 Python-тестов проходят. Они покрывают:

- пароль хранится хешем, токен — хешем, истечение сессии и отзыв при выходе;
- отказ в доступе без токена и к чужим чатам, прогонам, задачам, логам и архивам;
- запись/чтение истории и поиск; пустые сообщения отклоняются;
- сбой модели не сохраняет половину диалога и освобождает аренду;
- одновременный запрос в чат отклоняется;
- запуск, повтор с тем же ключом, конфликт параметров, обновление результатов;
- повторная синхронизация не дублирует задачи и артефакты;
- загрузка журналов, удаление известных секретов, скачивание и анализ прогона;
- ответы dispatch 200 и 204, восстановление по уникальному request ID;
- таймаут POST в GitHub трактуется как неопределённый исход и не повторяется;
- перенаправление скачивания не передаёт PAT в blob-хранилище;
- недопустимый адрес перенаправления отклоняется;
- модель вызывается с ограниченным контекстом, таймаут освобождает очередь;
- отсутствие GitHub не создаёт фиктивных прогонов;
- внешние ключи и запрет результата до завершения запуска.

JS-проверки клиента Авроры: 8 групп, включая форматы маршрутов, ответы API,
новые состояния, прекращение опроса, текстовые журналы и валидацию.
Python-код проверен Ruff; JS и Bash — на корректность синтаксиса.

## Что ещё не подтверждено

- Реальное подключение к GitHub и первый внешний pipeline: нужно опубликовать workflow и настроить доступ приложения.
- Сборка, `sfdk check`, подпись RPM, установка и запуск на Авроре: установщик скачан, но SDK ещё не установлен на исполнителе.
- Работа нативного интерфейса и C++-тесты в SDK.
- Развёртывание на постоянном сервере и доставка из GitHub.
- Качество ИИ-диагностики на размеченной выборке, нагрузка и многопользовательская работа.

Подмены GitHub используются только в тестах. В рабочем приложении нет демонстрационного
режима, который выдавал бы фиктивный прогон за настоящую сборку.
